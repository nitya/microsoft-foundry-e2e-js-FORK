## Concepts

### Prompt Engineering (minutes, no cost)

Prompt engineering is the fastest and cheapest way to customize a model. You write a **system prompt** (called `instructions` in the Responses API) that defines the assistant's persona, rules, and response format. The model follows these instructions on every call. It takes minutes to iterate and costs nothing beyond normal inference tokens. The limitation: the model can only reference knowledge it was trained on — it can't cite specific product SKUs or prices it has never seen.

### Context Engineering (hours, low cost)

Context engineering bridges the gap by injecting **real data into the prompt at runtime**. You load your product catalog from a CSV, search it for products relevant to the customer's question, and append the matching products to the system prompt. Now the model can reference specific names, SKUs, prices, and stock levels. This is sometimes called "grounding" or "retrieval-augmented generation (RAG) lite." It takes a few hours to build the search and formatting logic, and the only cost is slightly longer prompts (more tokens).

### Fine-Tuning (hours–days, medium cost)

Fine-tuning goes furthest: you train a **smaller, cheaper model** (like `gpt-4.1-mini`) on examples of ideal responses generated by a larger model (`gpt-4.1`). The smaller model learns the tone, product knowledge, and response patterns, so it can produce similar quality at lower per-token cost and faster latency. The tradeoff is time (training jobs take hours) and compute cost. Fine-tuning is ideal when you need consistent behavior at scale.

#### Step 2 — Understand the data pipeline

The script follows a three-stage pattern: **load → search → inject**.

**Load** — Read the product catalog CSV:

```python
def load_products(csv_path: str) -> list[dict]:
    with open(csv_path, newline="", encoding="utf-8") as fh:
        reader = csv.DictReader(fh)
        products = []
        for row in reader:
            products.append({
                "name": row["name"],
                "sku": row["sku"],
                "price": float(row["price"]),
                "description": row["description"],
                "stock_level": int(row["stock_level"]),
                "main_category": row["main_category"],
                "subcategory": row["subcategory"],
            })
    return products
```

**Search** — Find relevant products using keyword term-frequency scoring:

```python
def search_products(query: str, products: list) -> list[dict]:
    terms = query.lower().split()
    scored = []
    for product in products:
        text = f"{product['name']} {product['description']} " \
               f"{product['main_category']} {product['subcategory']}".lower()
        score = sum(1 for t in terms if t in text)
        if score > 0:
            scored.append((score, product))
    scored.sort(key=lambda x: x[0], reverse=True)
    return [product for _, product in scored[:5]]
```

**Inject** — Append matching products to the system prompt:

```python
def format_product_context(products: list) -> str:
    lines = []
    for p in products:
        lines.append(
            f"• {p['name']} (SKU: {p['sku']}, ${p['price']:.2f}) "
            f"— {p['description']} [Stock: {p['stock_level']}]"
        )
    return "\n".join(lines)
```

#### Step 3 — Understand the training workflow

The script follows five stages:

| Stage | What Happens |
|-------|-------------|
| **Upload** | Training and validation JSONL files are uploaded via the OpenAI Files API |
| **Process** | The platform validates and tokenizes the uploaded files |
| **Train** | A supervised fine-tuning job runs on `gpt-4.1-mini` (3 epochs, batch size 1) |
| **Deploy** | The fine-tuned model is deployed via `CognitiveServicesManagementClient` |
| **Cleanup** | Uploaded training files are deleted from the platform |

Key fine-tuning configuration:

```python
job = openai_client.fine_tuning.jobs.create(
    training_file=train_file_id,
    validation_file=val_file_id,
    model="gpt-4.1-mini",
    method={

        "supervised": {
            "hyperparameters": {
                "n_epochs": 3,
                "batch_size": 1,
                "learning_rate_multiplier": 1.0,
            },
        },
    },
    extra_body={"trainingType": "Standard"},
)
```

#### Step 5 — Compare all three approaches

| Approach | Time | Cost | Product Knowledge | Best For |
|----------|------|------|-------------------|----------|
| **Prompt Engineering** | Minutes | None | ❌ Generic only | Rapid prototyping, persona design |
| **Context Engineering** | Hours | Low (extra tokens) | ✅ Real-time from catalog | Dynamic data, RAG scenarios |
| **Fine-Tuning** | Hours–Days | Medium (training compute) | ✅ Baked into model | High-volume production, cost optimization |
